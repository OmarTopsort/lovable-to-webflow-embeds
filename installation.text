5. EXACT PAGE EMBED INSTALLATION

For every page in page-map.json:
1) Open its HTML file and locate the numbered PART and END PART comments.
2) Paste ONLY the code between each matching pair into one Webflow Code Embed.
   Keep CSS first, then HTML, then JS, in exactly the supplied order. Do not
   paste an entire large multi-part file into one Embed.
3) Name the Embed elements descriptively, for example "Tomi — PART 1 CSS",
   "Tomi — PART 2 HTML", etc., so later updates can replace the same elements.
4) Keep all parts on the SAME Webflow page. Continuation root wrappers and IDs
   are intentional. Do not remove them, merge parts, split a tag/function, or
   rename CSS classes, IDs, data attributes, inline SVG IDs or JS root arrays.
5) Keep the outer Webflow body/section wrappers full width, with no additional
   max-width, top padding, transforms or overflow clipping imposed on embeds.
   The embed supplies its own responsive layout. Do not add another H1 or hero.
6) Put required hidden CMS Collection Lists before the page's JS parts (see
   fields.md). They must exist when the scripts initialize; they cannot be
   lazy-loaded after initialization without an implementation change.
7) Remove the replaced content/old code once the correct new content is in place;
   do not stack new and old designs. Retain required hidden CMS data lists.
8) Files without PART markers are single snippets: global-head.html,
   global-body.html, and fall-update-2026.html. Follow their placement rules.

Each numbered part is checked below 49,000 characters. Webflow Code Embeds have
an enforced 50,000-character limit; they support HTML/CSS/JS and must not include
outer html/head/body tags. The provided page snippets already use fragments.
Reference: Webflow, Custom code embed
https://help.webflow.com/hc/en-us/articles/33961332238611-Custom-code-embed

Images are already hosted (Lovable/Webflow/font hosts) or embedded as data URLs.

All page CSS is inline; do not add relative ./style.css links or deploy /source's
